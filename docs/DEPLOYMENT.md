# Deployment, Demo Recording and Submission Checklist

Hosting: **Aiven** (free MySQL with TLS), **Render** (free backend), **Vercel** (web), **EAS Build** (Android APK).

Order matters: database, then backend, then web, then the CORS update, then the APK.

Rules for every step:
- Credentials go only into the provider dashboards (or a password prompt), never into Git, the README, screenshots or shell commands that end up in history.
- Do not reuse the local development database password or JWT secret.

---

## 0. Push the code to GitHub

Render and Vercel deploy from a GitHub repository. Create an empty repository (no README, keep it private until you are ready) while logged in to the GitHub account you want to use, then:

```bash
cd ~/full-stack-internship
git config user.name "<your name>"                  # this repository only
git config user.email "<email of that GitHub account>"
git add .
git status                                           # review: no .env, node_modules, dist, .apk
git commit -m "Project Management System"
git remote add origin https://<github-username>@github.com/<github-username>/<repo-name>.git
git push -u origin main
```

Putting the username in the remote URL makes Git ask for that account's credentials instead of reusing the GitHub login already saved in the macOS keychain. When asked for a password, paste a GitHub **personal access token** for that account (GitHub → Settings → Developer settings → Fine-grained tokens, with "Contents: Read and write" on this repository). The keychain stores it separately from the existing login.

## 1. Database (Aiven MySQL)

1. Sign up at [aiven.io](https://aiven.io) → **Create service** → **MySQL** → **Free plan**. Pick a region close to the Render region you will use.
2. When the service is running, open its **Overview** page. Note the **Host**, **Port** and the admin user `avnadmin` with its password. The default database is `defaultdb`.
3. Download the **CA certificate** from the same page and save it outside the repository, e.g. `~/aiven/ca.pem`.

### Create the tables

`docs/schema.sql` starts with `CREATE DATABASE` / `USE` lines for local development; skip them so the tables go into `defaultdb`. `-p` prompts for the `avnadmin` password, so it is not saved in shell history.

```bash
cd ~/full-stack-internship
sed '/^CREATE DATABASE/d;/^USE /d' docs/schema.sql | /usr/local/mysql/bin/mysql \
  --host=<aiven-host> --port=<aiven-port> --user=avnadmin -p \
  --ssl-mode=VERIFY_IDENTITY --ssl-ca="$HOME/aiven/ca.pem" defaultdb
```

### Create a dedicated application user

Generate a new password (letters, digits, `-` and `_` only, so it needs no URL encoding):

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

Connect as `avnadmin` (same command as above without the `sed ... |` part) and run:

```sql
CREATE USER 'pms_app'@'%' IDENTIFIED BY '<generated-password>';
GRANT SELECT, INSERT, UPDATE, DELETE ON defaultdb.* TO 'pms_app'@'%';
SHOW TABLES;
```

`SHOW TABLES` should list `projects`, `tasks` and `users`. The app user can read and write rows but cannot change the schema or other databases.

Your production connection string is:

```
mysql://pms_app:<generated-password>@<aiven-host>:<aiven-port>/defaultdb?ssl=true
```

`ssl=true` turns on TLS with certificate verification. Aiven signs its certificate with its own CA, so the backend also needs `NODE_EXTRA_CA_CERTS` pointing to `ca.pem` (step 2).

### Optional: test the connection from your Mac

The password is read from a hidden prompt, used once and discarded:

```bash
cd ~/full-stack-internship/backend
read -rs "DATABASE_URL?Production DATABASE_URL: " && echo && export DATABASE_URL
NODE_EXTRA_CA_CERTS="$HOME/aiven/ca.pem" npm run db:check     # prints DATABASE CONNECTED
unset DATABASE_URL
```

## 2. Backend (Render)

1. Decide your Vercel project name now (for example `pms-diya`), because the backend needs the web URL: `https://<vercel-project-name>.vercel.app`.
2. In [Render](https://render.com) → **New** → **Blueprint** → connect the GitHub repository. Render reads `render.yaml` and creates the `project-management-api` web service (free plan, root directory `backend`, build `npm ci && npm run build`, start `npm start`).
3. Render asks for the values marked `sync: false`:
   - `DATABASE_URL`: the connection string from step 1.
   - `CLIENT_ORIGIN`: `https://<vercel-project-name>.vercel.app` (no trailing slash).

   `JWT_SECRET` is generated by Render automatically (a new random value that you never need to see). `NODE_ENV=production` and `JWT_EXPIRES_IN=7d` come from the blueprint. Render sets `PORT` itself.
4. Open the service → **Environment** → **Secret Files** → add a file named `aiven-ca.pem` with the contents of `~/aiven/ca.pem`. It is mounted at `/etc/secrets/aiven-ca.pem`, which is where `NODE_EXTRA_CA_CERTS` points.
5. **Manual Deploy** → **Deploy latest commit** (the first automatic deploy fails until the secret file exists).
6. Check it:

   ```bash
   curl https://<render-service>.onrender.com/api/health
   # {"data":{"status":"ok"}}
   ```

   The logs should end with the server listening and no database errors.

## 3. Web (Vercel)

1. In [Vercel](https://vercel.com) → **Add New** → **Project** → import the GitHub repository.
2. Project name: the name chosen in step 2.1. **Root Directory**: `web`. Framework preset: **Vite** (build `npm run build`, output `dist`).
3. Environment variable: `VITE_API_URL` = `https://<render-service>.onrender.com/api`.
4. **Deploy**. `web/vercel.json` rewrites every path to `index.html` (so refreshing `/projects/<id>` works) and adds security headers, including a Content-Security-Policy.

If the project name you wanted was taken, update `CLIENT_ORIGIN` on Render to the real Vercel URL (Render redeploys automatically).

## 4. CORS check

`CLIENT_ORIGIN` must be exactly the Vercel production URL. Local development keeps working because local `.env` files have their own `CLIENT_ORIGIN`.

```bash
# Allowed: the response includes access-control-allow-origin with your Vercel URL
curl -s -o /dev/null -D - -H "Origin: https://<vercel-project-name>.vercel.app" https://<render-service>.onrender.com/api/health | grep -i access-control-allow-origin

# Not allowed: no access-control-allow-origin header, so browsers block it
curl -s -o /dev/null -D - -H "Origin: https://example.com" https://<render-service>.onrender.com/api/health | grep -i access-control-allow-origin
```

Vercel preview deployments use other URLs, so they are blocked by CORS by design; use the production URL.

## 5. Android APK (EAS Build)

The APK gets its API URL from an EAS environment variable, never from source code or a local `.env` (which is ignored by Git and not uploaded).

```bash
cd ~/full-stack-internship/mobile
npm install -g eas-cli
eas login                                    # your Expo account
eas init                                     # links the project; adds extra.eas.projectId to app.json
eas env:create --environment preview --name EXPO_PUBLIC_API_URL \
  --value https://<render-service>.onrender.com/api --visibility plaintext
eas env:list --environment preview           # confirm the URL is the HTTPS backend
eas build --platform android --profile preview
```

- Commit the `app.json` change made by `eas init`.
- The `preview` profile in `eas.json` builds an installable APK (internal distribution). The package name stays `com.diyashrestha.projectmanagement`.
- When the build finishes, EAS prints a page with the APK download link and QR code. Put that link in the README.
- If `EXPO_PUBLIC_API_URL` is missing from the build, the app shows "The app is not configured" instead of calling a wrong server.

The URL must never be `localhost`, `127.0.0.1`, `10.0.2.2` or a LAN IP: release Android builds block plain `http://`, and those addresses do not exist on a user's phone.

## 7. Cross-client demo recording plan

Before recording, open `<backend>/api/health` and wait for `ok` (cold start). Record the web part in the browser and the mobile part on a phone or emulator with the APK installed.

1. **Web: register** a new account (shows validation messages on an invalid form first).
2. **Web: log out and log in** with that account.
3. **Web: dashboard** shows zero totals.
4. **Web: create a project**, then open it.
5. **Web: create tasks** with different priorities, statuses and due dates.
6. **Web: search and filter** projects and tasks; mark one task complete and show the dashboard counts change.
7. **APK: log in** with the same account. The dashboard shows the same totals.
8. **APK: open the project**, see the tasks created on the web.
9. **APK: change a task** (mark it complete or edit its status), then **pull to refresh** the list.
10. **Web: reload** the page. The change made on the phone is shown, and the dashboard counts match.
11. **APK: create a task**; **web: reload** and show it.
12. **APK: log out**; it returns to the login screen. **Web: log out.**

- [ ] Backend deployed on Render; `/api/health` returns `ok` over HTTPS

- [ ] `CLIENT_ORIGIN` = exact Vercel URL; CORS check in step 4 passes
- [ ] APK built with EAS (`preview` profile) against the HTTPS backend; download link works
